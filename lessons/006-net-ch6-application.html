应用层：浏览器按下回车那一刻，到底发生了什么

五层协议我们已经爬了四层：物理层传比特、链路层传帧、网络层传分组、运输层把字节流交给进程。但「进程」内部——浏览器、微信、DNS 客户端——它们之间约定了什么内容格式和交互规则？这就是应用层协议。本章用一个贯穿问题驱动：在浏览器地址栏输入 www.example.com 并回车，到页面出现，中间发生了什么？这一问是面试最高频、也是期末综合大题的宠儿，答案就是本章目录：

完整链条（每一步本章都展开）：① DHCP 拿到自己的 IP（如果还没配）→ ② DNS 把域名翻译成 IP → ③ TCP 与服务器三次握手 → ④ HTTP 发请求收响应 → 浏览器解析 HTML，再为其中的图片、CSS、JS 重复 ②③④。
复习时把这句话倒过来当检查表：每一层学没学透，看能不能说清这一步里「哪个协议、报文长什么样、封装进什么」。

一、DNS：互联网的电话簿

为什么需要层次化的域名系统

设想只有一张中央表存「域名→IP」：全世界所有查询打到一个服务器，必然崩溃；而且域名增长无法管理。于是 DNS 用两个设计化解：分层命名（根 → 顶级域 com/cn/org → 二级域 example.com → 主机 www）和分权管理（每个域的 DNS 服务器只管自己这一层，像行政区划）。你抓包看到的 53 端口，就是这个分布式数据库的查询入口。

递归查询与迭代查询（必考辨析）

你的电脑 → 本地域名服务器 ：递归查询
  （「你务必给我最终答案」——本地服务器必须给出 IP 或报错）

本地域名服务器 → 根 → 顶级域 → 权威服务器 ：迭代查询
  （「我不知道，但你去问它」——每个被问的服务器只给下一步线索，
    本地服务器自己一层层跑腿）

实际优化：本地服务器有缓存（主机和各级服务器都会缓存，
TTL 控制有效期）——大部分查询根本到不了根服务器

此外记住两类记录：A 记录（域名→IPv4）、AAAA（→IPv6）、CNAME（别名→正式域名）、MX（邮件交换）；传输用 UDP 53（区域传送用 TCP 53）。

二、HTTP：万维网的通用语言

特点与报文结构

HTTP 的核心特征（简答背诵）：①无状态——服务器不记得你上次来过（ Cookie 是外挂的记忆补丁）；②基于 TCP——先握手再传，可靠；③灵活——可传输任意类型内容（Content-Type 区分）。请求报文 = 方法 + URL + 版本 + 首部 + 主体；响应 = 状态码 + 首部 + 主体。

常见方法：GET（取资源）  POST（提交数据）  HEAD（只要响应头）
状态码：1xx 信息 / 2xx 成功(200) / 3xx 重定向(301 永久 302 临时)
        4xx 客户端错(404 找不到 403 禁止) / 5xx 服务器错(500)

非持久连接 vs 持久连接（计算题）

HTTP/1.0 非持久：每请求一个对象都要新建 TCP 连接
  请求 1 个页面内含 5 张图 = 6 次握手 + 6 次传输，开销巨大
HTTP/1.1 持久连接：一次握手，多条请求复用
  流水线方式还可以不等应答连发请求
计算题模板：一个对象的时间 = 2×RTT（握手1 + 请求响应1）
  非持久 n 个对象 ≈ (n+1)×2×RTT + 传输时间
  持久流水线 ≈ 2×RTT + n×传输时间 —— 差别立现

HTTPS = HTTP over TLS（443 端口）。看第3章真实抓包：全是 TLSv1.2 Application Data——内容已加密，Wireshark 只能看到「在说话」，听不到「说什么」。这就是为什么现在抓明文 HTTP 要特意找 http:// 的老网站或自建服务器（实验里用 Packet Tracer 自建）。

三、DHCP：即插即用的地址发放

新设备接入网络，怎么自动拿到 IP、掩码、网关、DNS 服务器四件套？DHCP，UDP 67/68 端口，四步曲 DORA：

① Discover  客户端广播（0.0.0.0 → 255.255.255.255）：
            「有没有 DHCP 服务器？我需要一个 IP」
② Offer     服务器提供一个可用 IP（含租期）
③ Request   客户端广播正式申请这个 IP（可能有多个服务器都 Offer，
            广播让落选者也知道）
④ Ack       服务器确认租约，四件套生效

考点：为什么②④可以单播③却必须广播？
—— 严格说 DORA 全程多为广播实现（早期实现无 ARP 确认前）；
   Request 广播的核心理由是通知所有 Offer 过的服务器「我选了别人」

对照第4章的知识：Discover 用 255.255.255.255 受限广播——ARP 广播（第3章）在链路层 ff:ff:ff:ff:ff:ff，DHCP 广播在网络层全 1——两种广播的层次不同，综合题爱考。

四、其他应用协议速览

协议端口要点
FTP21 控制 / 20 数据两条并行 TCP 连接——控制信息带外传送，特色考点
SMTP25推协议：发件人→服务器→服务器
POP3 / IMAP110 / 143拉协议：服务器→收件人；IMAP 支持服务器端文件夹管理
SMTP+POP3 组合—邮件全程「推-推-拉」，中间两个 SMTP 一个 POP3

最后补充 P2P vs C/S 的对比：C/S 服务器是瓶颈（带宽随用户数线性增长），P2P 每个节点既是客户又是服务器，用户越多能力越强（自扩展性）——BitTorrent 的「下载即上传」。

五、🧪 动手实践（本章 2 个实验）

实验 1：Wireshark 抓 DNS 查询全过程

1. Wireshark 抓包开始，过滤器：dns
2. cmd 执行：nslookup www.xupt.edu.cn
   （或任何你没访问过的网站，保证缓存未命中）
3. 观察任务：
   a. Standard query 0xXXXX A www.xxx —— A 记录查询，UDP 53
   b. 应答里的 Answer 段：域名→IP 映射 + TTL（缓存有效期）
   c. 如果你配了多个 DNS，先看第4章的 ping 实验文件
      sample-mixed.pcapng——里面就有真实 DNS 交互
4. 进阶：cmd 执行 ipconfig /displaydns 看本机 DNS 缓存，
   与 Wireshark 抓到的「没再发出查询」相互印证

实验 2：Packet Tracer 综合组网 —— 自建迷你互联网

目标拓扑：
  PC0 ─┐
  PC1 ─┤ Switch ─── Router ─── 交换机区 ── Server-DNS (192.168.2.10)
                                        ├─ Server-Web (192.168.2.11)
                                        └─ Server-DHCP(192.168.2.12)

1. 按拓扑搭建，路由器两个接口分别 192.168.1.1 / 192.168.2.1
2. Web 服务器：Services → HTTP → 开启（编辑 index.html 写点字）
3. DNS 服务器：Services → DNS → 开启，
   添加 A 记录 www.myschool.com → 192.168.2.11
4. DHCP 服务器：Services → DHCP → 地址池 192.168.1.100~150，
   网关 192.168.1.1，DNS 192.168.2.10
5. PC0/PC1 的 IP Configuration 改为 DHCP ——
   自动拿到 192.168.1.10x，四件套齐了（DORA 在接口日志里可见）
6. PC0 浏览器访问 http://www.myschool.com —— 网页出现！
7. 切 Simulation 模式，过滤器勾选 DNS+DHCP+HTTP+TCP，
   重放整个「按下回车」的过程：DHCP 四步 → DNS 查询 → TCP 握手
   → HTTP GET/200 OK —— 你把第6章开头那条完整链条亲手跑了一遍
8. 故障演练（自测理解）：把 DNS 服务关掉再访问 ——
   页面打不开且提示无法解析域名；
   把 DNS 里记录删掉但保留服务 —— 同样失败，体会 A 记录的作用
