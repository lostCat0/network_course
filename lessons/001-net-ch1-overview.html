概述：网络到底是什么，数据怎么跑

这是整门课的地图。我们不从定义开始，而是从一个你每天都在做的动作开始——打开一个网页， 一路追问每个环节「为什么」，把这门课要用到的所有底层概念自然地引出来。

一、从一个场景开始：你按下回车之后

你在浏览器输入 www.baidu.com 并按下回车，0.2 秒后页面出现。这背后发生了什么？

你的电脑并不是网络里唯一的主人——家里还有手机、平板，公司有几百台机器。这些能上网的设备 （电脑、手机、服务器）在计算机网络里叫主机或端系统。「端」的意思是：它们位于网络的 边缘，是数据的最终发出者和最终接收者。而夹在它们中间的，是无数路由器、交换机和通信链路组成的 「网格」——这是网络的核心部分，它的任务只有一个：把数据从边缘的一台主机，搬运到边缘的另一台主机。

于是我们可以给出定义了：计算机网络 = 由若干节点（主机、路由器、交换机）和连接这些节点的链路组成， 实现资源共享与数据通信的系统。而把这些网络互相连起来形成的「网络的网络」，就是互联网（Internet）—— 它不是一张网，而是全球无数张网的互联体。

场景类比：端系统像千家万户，路由器像各个中转邮局，链路像公路。 你的信（数据）从家里发出，经过多个邮局（路由器）逐站转发，最终到达收件人家里。 后面讲的「交换方式」，本质上就是三种不同的「邮局工作模式」。

端系统之间怎么通信？两种方式

  • 客户-服务器方式（C/S）：一方提供服务，一方请求服务。你打开网页时，你的电脑是客户（发起请求）， 百度的服务器是服务器（等待并响应请求）——注意，「服务器」首先是一种角色，其次才指那台硬件机器。
  • 对等方式（P2P）：每台主机既是客户又是服务器，彼此直接传输。早期的 BT 下载就是典型：你下载电影的同时， 也在把它传给别人——没有中心服务器存储整部电影，每个人都是一个小「服务器」。

二、数据如何穿越网络：三种交换方式

现在到了本章的核心问题。场景：学校有 100 台电脑需要互相传数据， 电信运营商更夸张——几千万用户的数据要在同一批线路上跑。数据在核心部分怎么「走」？历史上给出过三种答案。

1. 电路交换：先占一条「专线」

最古老的答案来自电话网络。你打长途电话时有没有想过：这条线路是不是你们两人独占的？ 答案是——是的（至少传统电话是这样）。电路交换的流程：① 先建立连接（沿途每段线路都为你预留出一部分资源）， ② 通话（数据独占这条通路），③ 释放连接（挂机，资源归还）。

它的特点由此决定：通信前必须先建立连接（这叫「面向连接」）；一旦建立，数据传输实时、无时延抖动—— 非常适合电话这类实时通信。但代价巨大：资源独占。你打电话时并不总在说话， 沉默的每一秒里，那条为你独占的线路都白白浪费着。线路利用率极低。

2. 报文交换：像寄快递一样整块发

数据通信没有电话那么「连续」——你发一条消息、一个文件，是断续的、突发的。电路交换预留整条线路太浪费。 于是有了第二种思路：不需要建立连接，把整个数据块（叫一个「报文」）一次性发出。 沿途每个节点（交换机/路由器）先完整收到整个报文，检查无误后再转发给下一个节点——这叫存储转发。

存储转发是核心概念，后面所有内容都建立在它上面。它的问题也明显：报文可能非常大（一个几 GB 的文件）， 每个中转节点都要等整个报文全部到齐才能转发，节点需要巨大缓存，时延也很长。

3. 分组交换：切小了发，边到边转（互联网的答案）

第三种思路是报文交换的改良：把报文切成一个个较小的等长数据块（比如每块 1500 字节）， 每块前面加上首部（也叫包头）——首部里写着目的地址等控制信息。加上首部的数据块就叫分组（packet）， 所以互联网的核心部分也叫分组交换网，负责转发的路由器也叫分组交换机。

为什么切小块是革命性的？关键在于存储转发的流水线效应： 第一个分组一到路由器就能立刻转发，此时第二个分组还在路上，第一个分组的传输「占用了路由器但不再占用线路」—— 线路和节点在时间上重叠工作。而报文交换必须等全部数据到齐，线路空等。

三种交换方式是简答/计算题双料考点：① 各自特点与适用场景；② 时延计算（见下面例题）。记忆锚点：电路交换=先占线（电话），报文交换=整块存转（老电报），分组交换=切块流水线（互联网）。

经典计算题：三种方式到底差多少

例题：要发送 x = 10⁶ bit 的报文，途经 k = 3 段链路（即经过 2 个路由器）， 每段链路的发送速率为 b = 10⁶ bit/s，忽略传播时延和处理时延。比较三种方式的传输总时延。

  • 电路交换：忽略建立连接的时间，数据在 3 段线路上连续传输 → T = x/b = 1 s。（但别忽略：建立连接本身通常需要数秒，且这段线路被独占）
  • 报文交换：每个节点必须收完整个 10⁶ bit 才能转发，3 段链路逐段接力 → T = 3 × (x/b) = 3 s。
  • 分组交换：切成 p = 1000 bit 的分组，共 1000 个。第一个分组经过 3 段链路需要 3 × (p/b)， 之后每过一个分组时间只增加一个 p/b（流水线！）→ T = 3(p/b) + (1000−1)(p/b) = (x + (k−1)·p)/b = (10⁶ + 2×10³)/10⁶ ≈ 1.002 s。

分组交换几乎达到了电路交换的速度，又不需要独占线路——这就是互联网选择它的原因。 代价是什么？每个分组都要加首部（额外开销）、可能丢包、可能乱序到达（接收端要重排）。

三、衡量一张网络的尺子：性能指标

1. 速率与带宽

速率指每秒传输的比特数，单位 bit/s（也叫 bps，比特每秒）。 「比特」是信息量的最小单位（0 或 1），「字节（Byte）= 8 比特」——注意大小写： 大 B 是字节，小 b 是比特。100 Mb/s 的宽带下载速度最多约 12.5 MB/s， 这是新手最常见的困惑，现在你知道原因了。

带宽在计算机网络中有两种含义：① 频域上，信号所占据的频率范围（单位 Hz）——第2章物理层会用到； ② 时域上，链路的最高数据率（单位 bit/s）——日常说的「百兆带宽」是这一种。

单位换算是填空题常客：网络速率的 k/M/G 是 10³ 进制（10³、10⁶、10⁹）；而文件大小的 K/M/G 通常是 2¹⁰ 进制（1024）。所以 1 Mb/s ≠ 1 MB/s，差 8 倍还要再差 5% 左右。

2. 时延：数据在路上要花多久

总时延由四部分组成，前两种最常考、可计算：

  • 发送时延（传输时延）：主机/路由器把数据块的所有比特「推上」链路所需时间 = 数据长度 ÷ 发送速率。它是「机器往外吐比特的速度」。
  • 传播时延：一个比特在链路上从一端跑到另一端的时间 = 信道长度 ÷ 电磁波传播速率（铜线/光纤约 2×10⁸ m/s）。它是「比特在线路上飞的速度」。
  • 处理时延：路由器检查首部、查表选路、差错校验的时间。
  • 排队时延：分组在路由器输入/输出队列里等待的时间——堵车的时间，不确定，是丢包的根源（队列满了就丢）。

一个颠覆直觉的例子：在 1 Gb/s 的链路上发送 100 MB 的文件， 发送时延 = (100×2²⁰×8) bit ÷ 10⁹ bit/s ≈ 0.84 s； 而一个比特横穿 1000 km 光纤的传播时延只有 0.005 s。 高速链路提高的只是发送速率（吐比特的速度），并不会让单个比特在线路上飞得更快—— 「光纤里跑的是光，所以快」是最经典的误解：传播时延由物理距离和介质决定，与带宽无关。

3. 时延带宽积、RTT 与利用率

  • 时延带宽积 = 传播时延 × 带宽：这是「正在飞行的链路上最多容纳多少比特」， 想象成一节管道的体积（管道横截面是带宽，长度是传播时延）。发送方想暂停对方接收，管道里的比特也必须能存下。
  • 往返时间 RTT：从发送方发出数据，到收到对方的确认，总共经历的时间。衡量交互式应用（如网页点击）的关键指标。
  • 利用率：信道利用率越高越省钱，但排队时延随之暴涨。排队论给出 D = D₀/(1−U)—— 利用率 U 接近 1 时时延趋于无穷大。所以实际网络不会把利用率设计到 100%。

🔬 动手实验：测量你自己的网络时延与路径

Windows 键 + R 输入 cmd 打开命令行，依次运行：

ping www.baidu.com
ping www.baidu.com -n 20
tracert www.baidu.com
ipconfig /all

观察任务（对照学过的概念）：① ping 输出的「时间=xxms」就是一次 RTT—— 你亲手测出了往返时间；② 连续 ping 20 次看时延是否稳定、有没有丢包（「丢失=1」），波动大说明排队时延在起作用； ③ tracert 列出从你到百度途经的每一跳路由器——每一行对应一个「存储转发」的节点， 每行三个时间分别是三次探测的 RTT；④ ipconfig /all 里找到你的物理网卡（看「描述」）， 记下它的 MAC 地址（「物理地址」）——这是第2章会用到的概念，以及网关地址——数据离开你家网络的出口。

四、为什么要分层：协议与体系结构

最后回到全景：全球几十亿设备、成百上千种软硬件要互相通信，怎么可能设计得出来？ 答案不是「一个超能的协议」，而是分层。

场景类比：邮政系统

你给远方朋友寄一份合同：你写内容（应用的事）→ 装进信封写地址（打包与寻址）→ 邮局分拣、装车（传输调度）→ 火车/飞机运输（物理搬运）。每一层只关心自己的事， 下一层为上一层提供服务——写信人不需要懂火车调度，邮局不需要懂合同内容。 两层之间有约定（信封格式），同一层的两端之间也有约定（都写中文、都按同样格式写信封）—— 这种同一层的约定就是「协议」。

协议的正式定义：控制两个对等实体进行通信的规则的集合。三要素（必背）： 语法（数据格式与结构）、语义（每种控制信息做什么）、同步（事件实现顺序的详细说明）。

五层体系结构：把互联网的活儿分成五份

国际标准化组织曾提出七层的 OSI 参考模型（理论完美但过于复杂，没能占领市场）， 实际互联网用的是四层的 TCP/IP 体系。教学中我们使用五层模型——它综合了两者的优点，是考试的标准语言：

层次任务（用问题来记）处理的数据单元典型设备/协议
5 应用层「用户要做什么」——通过应用进程间的交互完成特定网络应用报文（message）HTTP、DNS、邮件协议
4 运输层「送到对方哪台机器的哪个程序」——为两台主机中进程间的通信提供服务报文段（TCP）/ 用户数据报（UDP）TCP、UDP
3 网络层「送到互联网上的哪台主机」——为分组交换网上的不同主机提供通信，选路分组（IP 数据报）IP 协议、路由器
2 数据链路层「在同一段链路的相邻节点间怎么传」——把网络层交来的分组组装成帧，在相邻节点间传送帧（frame）以太网协议、交换机、网卡
1 物理层「比特怎么变成信号在线路上传」——规定电气特性、传输媒体接口比特（bit）网线、光纤、集线器

发送方：数据从应用层往下走，每层加上自己的首部（像信套信封），到物理层变成信号发出； 接收方：从物理层往上走，每层剥掉自己这层的首部，处理自己该管的事，直到应用层还原出原始信息。 这个「层层加壳、层层剥壳」的过程叫封装——第3章起每一层都会看到它的具体形态。

高频考点：① 各层数据单元名称（比特/帧/分组/报文段/报文）排序题；② 协议三要素；③ 每层的核心任务（给一个功能描述，判断是哪层）；④ OSI 七层与 TCP/IP 四层的对应关系（考点：TCP/IP 没有专门的会话层和表示层，物理层+数据链路层合称网络接口层）。
