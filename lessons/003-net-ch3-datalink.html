数据链路层：把比特装进「快递箱」

第2章结束时，物理层已经能把一串比特（电平/光脉冲）从 A 传到 B。但请想一个新问题：物理层只会传比特，它不知道比特从哪开始、到哪结束——就像一段录音没有停顿和分句，听起来就是一串音节。电平序列 1101010001 里，哪个 8 位是一个字符？哪些是地址？哪些是校验码？物理层一概不知。

本章要解决的核心问题：把裸比特流切分成有边界的、可校验的单元——帧（Frame）。这是数据链路层的全部意义所在：它向上层（网络层）提供「看起来可靠的一段段传输」，向下驱动物理层传送比特。

一、三个基本问题（必考简答）

1. 封装成帧

在一段数据的前后分别加首部和尾部，构成一个帧。首尾部像快递箱的箱盖，作用有二：定界（接收方据此识别帧的开始和结束）和承载控制信息（地址、类型、校验）。所以教材反复强调：数据链路层看到的不是「数据+首尾」，而是「首部+数据+尾部」的整体。

一个细节：为什么帧的数据部分有长度上限（MTU，以太网 1500 字节）？因为如果数据太长，帧在链路上传输的错误率上升，且一旦出错整帧重传代价太大；太短又会导致首尾部开销占比过高。帧长是权衡出来的。

2. 透明传输

「透明」是网络中的术语：某层对上层不可见、无感知，就叫透明。这里的问题是：如果数据部分恰好出现了和「帧定界符」一样的比特模式，接收方会误判为帧结束。解决：

  • 字节填充（面向字节的协议如 PPP）：数据中出现的定界字节/转义字节前插入转义字节 ESC，接收方剥掉转义字节还原——像在正文中把引号转义掉。
  • 比特填充（面向比特的协议如 HDLC）：发送方每遇连续 5 个 1 就自动插一个 0，接收方每收到 5 个 1 就删掉后面的 0。

记忆钥匙：透明传输 = 无论数据是什么内容，都能原样通过链路层，上层完全不用关心。

3. 差错检测（CRC）

比特在传输中会因噪声翻转（1 变 0）。链路层用循环冗余检验 CRC 检测这类错误。计算过程是模 2 除法（不借位的异或除法），考试常给一个具体多项式让你算 FCS：

例题：数据 M = 101001（6 位），生成多项式 P = 1101（4 位 → 阶数 r = 3）
① 在 M 后补 r 个 0：101001000
② 用 101001000 对 1101 做模 2 除法（异或）：
   101001000
 ⊕ 1101
 ------
   011101000
 ⊕  1101
 ------
    001011000
 ...（继续除到底）
 最终余数 R = 001（r = 3 位）
③ 发送的帧 = M 后拼接 R = 101001001
④ 接收方用收到的整串再除以 P，余数为 0 → 认为无错
考点三连：①CRC 只能检错不能纠错（能定位错在哪类的说法都错）；②CRC 除法是模 2 运算（加减都是异或，无进位借位）；③补 0 的个数 = 生成多项式最高次数 r（多项式 1101 是 4 位，r=3，不是 4）。

二、点对点信道：PPP 协议

用户接入互联网（如拨号、PPPoE 宽带）用的是点对点链路——一条线两端各一个节点，不存在「谁抢信道」的问题。PPP（Point-to-Point Protocol）就是这种场景的标准协议，组成三部分（简答题）：

  • 一个封装方法：帧格式 = 标志 F(7E) + 地址 F(FF) + 控制 F(03) + 协议 + 数据 + FCS + 标志 F(7E)。
  • LCP（链路控制协议）：建立、配置、测试、拆除链路连接——先「谈好」参数（MTU、认证方式）再传数据。
  • NCP（网络控制协议）：协商网络层参数，最典型是为拨入用户动态分配 IP 地址。
经典简答：PPP 帧为什么不需要序号和确认机制？因为数据链路层「可靠传输」的代价（重传、缓存）在误码率不高时得不偿失，互联网已把可靠传输的责任交给运输层 TCP。PPP 采用「无序号、无确认、检错丢弃」的策略——FCS 检出错的帧直接丢弃，纠正交给上层。这体现了分层设计的取舍思想，也是「不可靠交付」一词的含义。

三、广播信道：CSMA/CD 与以太网

场景引入：宿舍抢一个洗手间

早期以太网是总线型：所有主机挂在同一条总线上，任何一台发送，所有主机都能收到（广播信道）。这带来三个问题，恰好对应 CSMA/CD 协议的三个动作——想想多个人抢一个洗手间：

洗手间场景CSMA/CD 对应动作
进门先看有没有人（载波侦听）CS：载波侦听——发送前先检测信道是否空闲
进去后继续留意外面有没有人排队（多点接入）MA：多点接入——多台主机竞争同一信道
两个人同时推门 → 冲突，都退出择时再来（冲突检测）CD：冲突检测——边发送边监听，检测到冲突立即停止，执行退避算法

争用期与最短帧长（计算题重灾区）

冲突检测有一个物理极限：信号传播需要时间。A 发出的信号要经过传播时延 τ 才到 B；最坏情况下，A 发出后近 2τ 才能确认自己发的帧有没有撞车。这段 2τ 称为争用期（冲突窗口）。由此推出必考结论：

以太网取争用期 2τ = 51.2 μs（传统 10 Mbit/s）
最短帧长 = 争用期 × 发送速率 = 51.2μs × 10Mbit/s = 512 bit = 64 字节

推论：帧长 < 64 字节 → 发完都没过完争用期 → 冲突可能没被检测到
      → 这不是正常帧，会被接收方直接丢弃

10M 以太网最大帧长 1518 字节则是 MTU 1500 + 首尾 18 字节

发生冲突后采用二进制指数退避：第 i 次冲突后，从 {0,1,…,2^k−1}（k=min(i,10)）中随机选一个数 r，等待 r×2τ 再重试；16 次仍失败则放弃并报错。反复冲突说明网络拥挤，指数退避让重传时间自动拉长——「越堵越让」。

四、以太网帧与 MAC 地址（对照真实抓包讲解）

我在你的电脑上用 Wireshark 抓了一段真实流量，下面是一条真实存在的 ICMP 帧（ping 百度的包）：

目的 MAC  74:08:aa:99:5c:16   ← 6 字节，这是网关的网卡地址
源 MAC    b8:1e:a4:ba:cb:0b   ← 6 字节，这是你电脑的网卡地址
类型      0x0800              ← 2 字节，表示上层是 IP 数据报
数据      IP 报文（含 ICMP ping）
FCS      （Wireshark 默认不显示，由网卡硬件校验）

类型字段速查：0x0800 = IPv4   0x0806 = ARP   0x86DD = IPv6

MAC 地址（物理地址/硬件地址）48 位，烧录在网卡 ROM 中，前 3 字节是厂商标识（OUI），后 3 字节是厂商自定编号。注意理解：MAC 地址是「这一段链路」的地址，IP 地址是「端到端全程」的地址——快递类比：IP 是收件人住址（全程不变），MAC 是每一段运输的承运人（每过一跳就换）。这个区别在第4章讲 ARP 和路由时会再证一遍。

MAC 帧考点：①最短 64 字节包含 18 字节首尾部，所以数据部分最短 46 字节（不足要填充）；②类型字段标识上层协议；③ff:ff:ff:ff:ff:ff 是广播地址——发往它的帧交换机会泛洪到所有端口；④网卡对不是发给自己（也不广播/组播）的帧直接丢弃（混杂模式除外，这正是 Wireshark 能抓别人包的原理）。

五、从集线器到交换机（Packet Tracer 实验 1 预习）

设备工作层次转发方式碰撞域
集线器 Hub物理层把信号复制到所有端口（电平再生）所有端口同属一个碰撞域，仍然要跑 CSMA/CD
网桥/交换机数据链路层按 MAC 表精准转发/过滤每个端口一个独立碰撞域
路由器网络层按 IP 转发表转发既隔离碰撞域，也隔离广播域

交换机的聪明来自自学习算法：收到帧时，把「源 MAC → 入端口」写进 MAC 地址表（老化时间通常 5 分钟）；查「目的 MAC」在不在表里——在就转发到对应端口，不在就泛洪（发往除入端口外的所有端口）。MAC 表逐渐学全后，单播帧就只走一条精准路径，冲突被彻底隔离。自学习过程 Packet Tracer 的 Simulation 模式能一帧一帧看（实验 2）。

六、VLAN：在交换机上「切」出逻辑子网

交换机虽然隔离了碰撞域，但广播域还是一整个：ARP 广播、DHCP 广播会打遍全网，规模一大性能崩溃且有安全隐患。VLAN（Virtual LAN）在以太网帧里插入 4 字节 802.1Q 标签（插在源 MAC 之后），把同一台物理交换机的端口划进不同的逻辑广播域——不同 VLAN 的主机即使插在同一交换机上，二层也完全不通，必须经过路由器（第4章实验会配）。

实验 1：Wireshark 分析真实 ARP（有现成抓包文件）

我已在你的 WLAN 网卡上真实抓取了流量样本，保存为课程附件。操作：

1. 打开 D:\WireShark\Wireshark.exe
2. File → Open → 选择 D:\WorkBuddy_workspace\2026-11-10-09-39-22\network-course\assets\captures\sample-mixed.pcapng
3. 在显示过滤器输入：arp        （回车）
4. 观察任务（对照本章概念）：
   a. 找 "Who has 10.134.46.253? Tell 10.134.46.202" 的包——
      看它的以太网目的 MAC 是不是 ff:ff:ff:ff:ff:ff（广播！）
   b. 看 ARP 请求里目标 MAC 字段填的是什么（00:00:00:00:00:00 —— 还不知道，先占位）
   c. 找对应的应答包 "10.134.46.253 is at 74:08:aa:99:5c:16"——
      注意它是单播回给询问者的，且应答里的源 MAC 就是 74:08:aa:99:5c:16
   d. 彩蛋：抓包里 10.134.46.1 和 10.134.46.253 两个 IP 应答的是
      同一个 MAC —— 这是网关冗余（VRRP 类）的真实证据

然后输入过滤器 eth.type==0x0806 应得到同样的包——体会「类型字段 0x0806 = ARP」这个帧格式知识点的实际用法。再试 eth.addr==ff:ff:ff:ff:ff:ff 看看广播流量有多少。

实验 3：Packet Tracer —— 集线器 vs 交换机 + VLAN

实验 3a：碰撞域对比
1. 拓扑：PC0、PC1 各连一台 Hub（Hub 再互连）；PC2、PC3 连另一台 Switch（Switch 互连）
2. 全部配同网段 IP（如 192.168.1.1~4/24）
3. Simulation 模式：让 PC0 ping PC2，观察 Hub 这边「复制到所有端口」
   vs Switch 这边「只走学习到的端口」
4. 思考：PC0 和 PC1 同时互 ping，Hub 侧会怎样？（冲突→CSMA/CD 重传）

实验 3b：VLAN 划分（交换机 CLI）
1. 一台 2960 交换机接 4 台 PC（Fa0/1~4），IP 同 192.168.1.0/24
2. 在交换机 CLI：
   enable
   configure terminal
   vlan 10
    name STUDENTS
   vlan 20
    name TEACHERS
   interface range fa0/1-2
    switchport mode access
    switchport access vlan 10
   interface range fa0/3-4
    switchport mode access
    switchport access vlan 20
3. 验证：VLAN10 内 PC1 ping PC2 通；跨 VLAN PC1 ping PC3 不通
4. show vlan brief 查看划分结果
5. 思考：跨 VLAN 不通，谁能让它通？（第4章「路由」揭晓）
